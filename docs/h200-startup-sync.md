# H200 启动同步包

应用启动并确认 H200 协议接口可独占访问后，会立即生成并发送一份完整按键包。

## 数据来源

- UI 和发送包共用 `DeckKeyDisplay`。
- 启动时先通过 `UserDefaultsDeckConfigurationStore` 尝试恢复用户上次保存的页面树配置；没有保存内容、保存内容损坏或布局不匹配时，回退到 `DeckGridInteractionState(layout: .h200Prototype)` 的默认第 1 个主页配置。旧版 flat 14 格配置会迁移为第 1 个主页。
- 根层支持最多 10 个有序主页，页面选择器在根层显示 `1, 2, 3...` 标签，并在标签右侧提供新增页面按钮；达到 10 页后新增按钮不可用。功能夹内不显示主页新增或删除入口，只显示当前主页到功能夹的路径。
- 初始包总是从第 1 个主页生成。页面树会持久化每个主页、每个功能夹子页的 14 个格子和嵌套关系，但当前停留页面只属于运行时状态，不写入 `UserDefaults`；应用重启、重新发现设备或重新同步后都会回到第 1 个主页。
- 进入功能夹后会开始 30 秒空闲倒计时，点击任意实体按键会重置倒计时，倒计时结束后自动返回上级；嵌套功能夹会逐级计时返回。
- 初始包使用恢复后的 `DeckGridInteractionState.displays(for: .h200Prototype)` 生成当前页 14 个格子的标题和副标题。
- 当前显示内容是每个格子的功能状态和参数摘要；默认配置下第 1 个主页每个格子都是 tally，当前值和默认值都是 `0`。新增主页时会插入到当前主页后并立即切到新主页：按键 1...13 初始化为空功能，按键 14 只继承当前主页的显示模式（功能、时钟或系统状态），不继承功能或参数；如果按键 14 继承到 `功能` 显示，也仍然是空功能。新建页面文件夹时，子页面第 14 个宽槽位默认继承父页面当时的第 14 个宽槽位显示模式，但不继承父页面第 14 个宽槽位的功能配置；按键 13 默认放置返回键，返回键默认显示名称为空且不变暗。页面文件夹默认名为“功能夹”，功能列表和默认按键背景都使用系统 `folder` 符号；Finder 打开文件夹功能保持原来的“打开文件夹”文案和 `FolderBackground` 默认背景。每个按键配置都使用按键级 `DeckKeyVisualConfiguration` 保存显示名称、自定义背景图、高斯模糊开关和变暗开关；右侧参数面板把这些视觉控制统一放在“功能”下面。选择背景时，选择器附件下拉为“图像”会读取图像本身并生成最长边不超过 `512px` 的原图与高斯模糊版本，原图不足该尺寸时不放大；下拉为“所有文件”会读取所选文件的系统 icon 并生成同样两版。打开文件夹、SMB 和游戏默认背景在 app 内只打包最长边 `512px` 的 PNG 源图，不打包预生成缩略图；打开网页、页面文件夹和返回键默认背景运行时分别从系统 `globe`、`folder` 和 `arrow.uturn.left` 符号生成；上一页和下一页功能默认背景运行时分别从系统 `chevron.left` 和 `chevron.right` 符号生成；填写网页地址后会异步获取网页标题和 icon，标题作为该功能的自动显示名，icon 作为该按键实例的默认背景；运行时按每个按键实例生成默认原图和高斯模糊背景数据，删除按钮功能后这些实例背景数据会随配置一起清空。清除自定义背景后会回到该实例自己的默认背景来源：打开文件优先使用所选文件 icon，打开网页使用已获取的网页 icon、未获取前使用系统 `globe` 符号，打开文件夹使用 `FolderBackground` 源图，页面文件夹使用系统 `folder` 符号，返回键使用系统 `arrow.uturn.left` 符号，上一页和下一页使用对应 `chevron` 符号，SMB 使用 `SMBServerBackground` 源图，游戏状态使用对应游戏源图，其余功能使用黑底。参数面板的“高斯模糊”和“变暗”都是按键级设置，每个实例可以独立切换。顶部亮度 slider 只控制设备亮度，不占用任何按键格子。
- 第 14 个格子对应协议里的 `3_2` 宽槽位，占 2 列；UI 也按 2 列宽显示，避免 app 预览和设备包布局不一致。

## 包格式

- 发送内容是 ZIP payload。
- ZIP 根目录包含 `manifest.json`。
- 每个格子的 PNG 放在 `Images/key_<id>.png`。
- `manifest.json` 使用零基坐标键，例如 `0_0`、`3_2`。
- `3_2` 宽槽位写入 `SmallViewMode: 2`，让固件按 458×196 的宽图处理。

## HID 分片

- 完整包使用命令 `0x0001` 发送。
- 第一个 HID report 是 1024 字节：
  - `0x7c 0x7c`
  - 2 字节大端命令
  - 4 字节小端 payload 长度
  - 最多 1016 字节 payload
- 后续 report 每包 1024 字节，末包补零。
- 生成 ZIP 后会检查固件问题：payload 偏移 `1016 + 1024 * N` 的字节不能是 `0x00` 或 `0x7c`。如果命中，会加入 padding 文件并按 1 字节步长重建 ZIP，直到避开这些分片边界。
- 完整按键包发送后，会追加一条 `0x0006` 小窗数据包，按 `3_2` 宽槽位当前显示模式设置小窗。`功能` 对应 `BACKGROUND(2)` 并显示自定义 PNG，`时钟` 对应 `DIAL(1)`，`系统状态` 对应 `STATS(0)`。

## 连接生命周期

- 参考实现没有要求按固定周期重发完整 `0x0001` 按键 ZIP 包；完整包在初始化或布局内容变化时发送。
- 当前原型在短按计数、长按重置、修改默认值、修改文件夹/文件/网页参数或修改 SMB 地址后，只用 `0x000d` 局部更新包同步当前页面对应单个格子的当前可见状态。
- 进入页面文件夹、返回上一级页面、添加主页、删除主页或在主页间翻页都会切换当前运行时页面，并重新发送一份完整 14 格显示包；隐藏页面上的定时刷新、长按和异步请求会在导航前取消，导航后只启动当前可见页面需要的运行时任务。
- 删除主页只能在根层对当前主页执行，右击当前页标签后会先弹确认；确认后删除该主页及其下属功能夹子树，至少保留 1 个主页。删除后切到前一页；删除第 1 页时显示新的第 1 页。
- 顶部亮度 slider 变化会先更新 app UI 和本地配置，再通过后台串行任务发送 `0x000a` 亮度包；slider 左侧的“跟随屏幕”复选框启用后，每 `0.25` 秒读取一次 Mac 内置屏亮度，只在数值变化时更新 Deck，并把内置屏 `0%...70%` 线性映射为 Deck `0%...100%`（超过 `70%` 时封顶为 `100%`）。同一开关还会每 `0.5` 秒读取一次 macOS Night Shift 状态和强度：关闭时保持 6500K 原色，开启时把 `0%...100%` 线性映射到 `6500K...2500K`，通过 Core Image `CITemperatureAndTint` 重新渲染并同步当前页按键 PNG；设备固件自行绘制的时钟和系统状态小窗不受该颜色处理影响。跟随状态会持久化，跟随期间手动 slider 禁用。如果发送期间 UI 继续变化，只保留最新百分比，当前发送成功后再发送最新值，避免亮度包堆积。
- 内置屏亮度通过 `DisplayServicesGetBrightness` 读取。该接口在 App Sandbox 中返回 `CGError 1000`，因此当前 app 的 Debug/Release 构建均不启用 App Sandbox。第一次从旧沙盒版本启动时，如果新的标准偏好域还没有 Deck 配置，app 会从原容器 plist 一次性复制按键配置、亮度、亮度跟随状态和 Sub2API 凭据索引；原容器文件不会删除，可继续作为恢复来源。
- Shortcuts 的亮度调节器只在 app 正在运行且 H200 已完成同步时临时发送 `0x000a` 亮度包，不保存亮度配置，也不会主动打开 app。
- 亮度从 app 内 slider 或 Shortcuts 设为 `0` 时，会立即暂停内部刷新：Sub2API 号池/余额、米游社游戏状态、小窗时钟和 CPU/RAM/GPU 系统状态都停止定时请求或保活；亮度恢复到大于 `0` 后会恢复小窗保活，并立刻刷新当前可见页面的 Sub2API 和游戏状态。
- 用户修改按键功能、修改默认值、文件夹路径、文件路径、页面文件夹结构、主页列表、亮度百分比、亮度跟随状态、物理短按计数和长按重置后，会同步写入本地 `UserDefaults`，下次启动用同一份页面树的第 1 个主页生成首包。
- app 会在启动同步成功后持续持有 H200 协议 HID 接口连接，直到重试、退出或同步器释放。
- 参考实现里 5 秒 `keepAlive` 针对小窗时钟/状态数据，不是完整按键包刷新。
- 当前原型会在启动同步后继续保活：1 秒后先发送一次当前小窗模式的 `0x0006` 数据，之后每 2 秒重复发送一次，避免 H200 在几秒后恢复离线/默认显示。时钟模式的保活包会带当前时间；亮度为 `0` 时保活会暂停，但不会关闭 HID 连接或阻止亮度/按键包发送。

## 发包线程边界

- `H200HIDConnection.writePackets(_:)` 是通信层唯一 HID 写入口，通过内部串行队列同步执行，逐包调用 `IOHIDDeviceSetReport`，调用返回即表示本批写入已结束或已经得到写入错误。
- `H200DeckSyncing` 暴露的发包函数保持同步阻塞：`sendStartupPackage(displays:)`、`sendPartialPackage(displays:)`、`setBrightness(percent:)` 都只在 PNG/ZIP 构建或本次 HID 写入完成后返回。
- `H200DeckSyncResult` 和 `H200DeckCommandResult` 都携带 `elapsedNanoseconds` / `elapsedMilliseconds`。完整包和局部包的耗时包含排队进入设备同步器、PNG/ZIP 构建、HID 打开/写入和返回；亮度命令的耗时包含排队进入设备同步器、HID 打开/写入和返回。
- SwiftUI 状态层不在主线程直接调用阻塞设备函数。`H200ConnectionModel` 统一通过后台 `deviceCommandQueue` 串行执行发现、关闭、完整同步、局部同步和亮度命令，再回到主线程更新 `status`、`syncSummary` 和 `alert`，因此发包期间 UI 仍可响应。
- 如果用户在启动完整包尚未返回时修改格子，应用会先记录显示版本变化；启动包完成后自动补发一次当前完整显示，避免设备停留在启动时的旧画面。

## 当前边界

- 启动时发送完整按键包，并追加一次当前小窗模式包。
- 保活只发送当前小窗模式的小包，不周期性重发完整按键 ZIP。
- tally、文件夹、文件、网页、SMB 和当前页面内普通配置状态变化后使用 `0x000d` 局部更新；payload 仍然是 ZIP，`manifest.json` 只包含本次变化的单个格子，图片也只包含该格子的 PNG。
- 页面文件夹导航、返回导航、添加/删除主页和主页翻页不使用局部更新，而是发送完整 `0x0001` 14 格包，确保设备端直接切到目标页面的完整画面。
- 宽槽位切到 `时钟` 或 `系统状态` 时会先清空该槽位当前页的功能，并用 `0x000d` 发送一张透明宽图清掉设备上的旧自定义背景；同一批局部更新会附带 `0x0006` 小窗模式包切到 `DIAL(1)` 或 `STATS(0)`。切回 `功能` 时继续发送宽槽位局部 PNG，并附带 `BACKGROUND(2)` 小窗模式包恢复自定义显示。各主页的第 14 个宽槽位显示模式和功能配置互相独立；给某个主页的第 14 键分配功能不会影响其他主页。
- `STATS(0)` 小窗 payload 使用 `${mode}|${cpu}|${mem}|${time}|${gpu}|${format}|${suffix}`。CPU 和内存来自 Mach host statistics，GPU 优先读取 `IOAccelerator` 的 `PerformanceStatistics["Device Utilization %"]`，读不到时退回 `Renderer/Tiler Utilization %` 的较大值，仍读不到则发 `0`。
- app 内修改顶部亮度百分比或 Shortcuts 亮度调节器动作时，只发送 `0x000a` 简单包；payload 是 UTF-8 百分比数字，例如 `"50"`。
- Sub2API 请求返回令牌无效/过期后，该页面对应按键会停止自动和手动请求，直到认证信息再次变化才恢复；普通网络错误不会暂停，会继续按各自刷新间隔重试。
- Sub2API 的“数据来源”默认是“自定义”，也可以引用另一个 Sub2API 号池或余额按键配置；所有 Sub2API 查询通过公共 `Sub2APIDataSourceConfiguration` 入口解析来源。同类型引用共享来源根的 Base URL、认证和刷新间隔；跨类型引用只共享 Base URL 和认证，号池与余额仍按各自刷新间隔、各自端点请求。切回“自定义”或来源根失效时，引用者解除引用并清空 Base URL 与认证，等待用户重新填写。数据来源只允许引用完全自定义的根实例：已经引用其他实例的配置不会再出现在候选项中，已经被其他配置引用的实例也不能再改为引用第三个实例。加载和编辑统一拒绝自引用、同类型循环和跨类型循环。
- 当前页面中使用同一号池数据来源的按键只请求一次完整组列表，再按各自独立保存的目标分组显示结果；切换分组会优先复用已有组列表，不重复请求。使用同一余额数据来源的按键一次刷新只请求一次 `GET {Base URL}/api/v1/auth/me`，读取成功响应的 `data.balance`，再把结果分发给全部余额消费者；即使余额与号池引用同一来源，也不会合并不同端点的请求。
- 余额按键配置包含数据来源、Base URL、刷新间隔、认证信息、服务名和单位。单位默认为 `$`；整数不显示小数，非整数保留两位，不做货币换算。成功时按键显示“服务名 / 余额 / 单位 数值”，失败时保留前两行并把第三行显示为“失败”。物理按键点击和定时器都可触发刷新。
- SMB 地址只允许服务器、可选端口和共享路径，不接受 URL 中的用户名、密码、query 或 fragment；认证统一交给 macOS 系统窗口，连接日志也只记录移除凭据和附加参数后的地址。
- 每个 Sub2API 按键配置通过公共来源入口关联凭据 ID；Bearer Key 只保存在 Keychain，UserDefaults 页面配置只保存凭据 ID。自定义数据来源只支持手动输入认证信息；引用其他数据来源时使用来源根的认证。合法共享的 credential ID 会由同一 Keychain 项服务多个消费者，不再人为复制；来源刷新或手动更新会同步同 ID 的跨页消费者，并由持久化层按单一逻辑 owner 聚合写入，旧 bearer 不会覆盖新 token。明确清空任一共享 owner 的 Bearer Key 时，所有同 ID 消费者同时清空 bearer 和 credential ID；保存随即将该 ID 视为无引用并删除 Keychain 项，重启加载不会复活旧 token。临时把按键切换成其他普通功能时会保留该配置的凭据，清空按键或删除所属页面后也进入清理流程；清理失败的凭据 ID 会保留在索引中等待后续重试。旧版配置中的明文 Bearer Key 会在加载时迁移到 Keychain，并立即从 UserDefaults payload 中移除；迁移失败时同样移除明文和凭据 ID，并将该按键视为未填写凭据，安全优先。加载配置时先完成页面和按键结构归一化，再迁移最终保留的凭据。
- 米游社游戏状态返回需要登录或登录失效后，会清除共享会话、取消所有游戏状态刷新并标记游戏按键需要重新登录；普通网络错误不会清登录，也不会暂停自动刷新。
- 亮度不再是按键功能，物理按键不会触发亮度调节。
- 如果发送阶段发现端口被 Ulanzi Studio 或其他软件占用，会显示“按键包尚未发送”的错误提示。
